AUREON Database Table Design & BCNF Normalization
Role Table
Purpose: Stores the different user roles (Business Architect, Project Manager, Team Lead, Developer, Tester) used for role-based access control.
tbl_role
FieldData TypeKeyDescription
role_id (PK)INTPrimary Key (PK)Description of role_id (PK).
role_nameVARCHAR(50)-Description of role_name.
is_activeBOOLEAN-Indicates whether the record is active (1 = Active, 0 = Inactive).
is_deletedBOOLEAN-Indicates whether the record has been soft deleted (0 = Not Deleted, 1 = Deleted).
Normalization Verification: ✅ Boyce-Codd Normal Form (BCNF)
  • role_id → role_name, is_active, is_deleted
1NF: All attributes contain single atomic scalar values.
2NF: PK is single-column (role_id); no partial dependencies exist.
3NF: No non-key attribute determines any other non-key attribute (no transitive FDs).
BCNF: The sole determinant (role_id) is a superkey/candidate key.
User Table
Purpose: Stores user registration and login information along with profile details, role, and team assignment.
tbl_user
FieldData TypeKeyDescription
user_id (PK)INTPrimary Key (PK)Description of user_id (PK).
user_nameVARCHAR(100)-Description of user_name.
user_emailVARCHAR(100)-Description of user_email.
user_passwordVARCHAR(255)-Description of user_password.
user_phoneVARCHAR(15)-Description of user_phone.
user_employee_idVARCHAR(30)-Description of user_employee_id.
role_id (FK)INTForeign Key (FK)Description of role_id (FK).
team_id (FK)INTForeign Key (FK)Description of team_id (FK).
user_statusENUM-Description of user_status.
user_created_atDATETIME-Description of user_created_at.
is_activeBOOLEAN-Indicates whether the record is active (1 = Active, 0 = Inactive).
is_deletedBOOLEAN-Indicates whether the record has been soft deleted (0 = Not Deleted, 1 = Deleted).
Normalization Verification: ✅ Boyce-Codd Normal Form (BCNF)
  • user_id → user_name, user_email, user_password, user_phone, user_employee_id, role_id, team_id, user_status, user_created_at, is_active, is_deleted
  • user_email → user_id (Candidate Key)
  • user_employee_id → user_id (Candidate Key)
1NF: All columns contain atomic attributes.
2NF: Primary key user_id is non-composite; no partial key dependencies.
3NF: Non-prime attributes depend solely on candidate keys.
BCNF: All functional determinants (user_id, user_email, user_employee_id) are Candidate Keys.
